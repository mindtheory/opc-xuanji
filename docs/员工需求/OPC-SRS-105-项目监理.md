# 项目监理 员工需求规格说明

## 1. 定位与边界

项目监理是一人公司的**项目全生命周期管理角色**：从商机/立项、范围、计划、执行、监控，到验收、收尾与复盘；以里程碑和细化任务为骨架，以甘特图/基线/关键路径为可视化与偏差控制手段，并与公司目标管理（OKR）联动。对软件研发项目，额外管理版本库（Git/SVN）、制品仓库（Maven/Docker）、部署环境（SSH）、发布/回滚与测试证据链，并协同专门测试 Agent 完成测试执行与报告。

| 视角 | 职责 |
| :--- | :--- |
| 项目负责人 | 立项、章程、范围、阶段门、验收与收尾 |
| 计划经理 | WBS 联动、里程碑、任务、依赖、资源与排期、基线 |
| 监控者 | 甘特图、关键路径、进度/成本/范围偏差、风险与问题 |
| 目标管理者 | 项目目标/里程碑与 OKR 对齐、进度回卷、风险提示 |
| 交付协调者 | 交付物、质量、验收、开票/回款联动、状态报告 |
| 复盘组织者 | 收尾、经验教训、知识沉淀、模板改进 |

**边界**：

- WBS 员工负责工作分解、工作包编码与基线变更；项目监理消费 WBS 结果，不重复拆解。
- 项目监理不代替老板做项目取舍、资源优先级、客户承诺与验收终审；只呈报事实、偏差、风险与选项。
- 不伪造进度、验收、回款或干系人确认；无证据的完成状态只能标“待核实”。
- 验收终审、重大范围/预算变更、项目终止必须 human gate；高风险节点 `timeout_policy=hold`。
- 版本库/制品库/SSH 凭据只存引用（`auth_ref`），不落明文、不进日志、不随员工包导出；生产发布与回滚必须老板或授权人确认。
- 测试 Agent 只提供测试证据与建议，不替老板做发布/验收终审；未执行的测试不得计为通过。

## 3. 功能需求

### 3.1 REQ-PRJ-001 全生命周期阶段模型与阶段门

**需求陈述**：按“商机/立项 → 范围 → 计划 → 执行 → 监控 → 验收 → 收尾/复盘”管理项目；每个阶段有入口条件、交付物、退出标准和阶段门审批。

**验收标准**：

- **AC-1** `project` 含 `lifecycle_stage`、`stage_status`、`stage_gate`、`owner`、`start_date`、`target_end_date`、`actual_end_date`。
- **AC-2** 每个阶段定义入口条件、必备交付物、退出标准与审批人；未满足退出标准不得进入下一阶段。
- **AC-3** 阶段门审批记录审批人、时间、结论、附条件；驳回/附条件整改可追踪。
- **AC-4** 项目终止/暂停/重启必须写审计并保留历史阶段记录，不删除项目。
- **AC-5** 阶段模型支持按项目类型（服务/交付/研发/贸易/混合）配置模板，不硬编码单一流程。

追溯：AC 直验 / `project_stage_gate` 流程

### 3.2 REQ-PRJ-002 立项与项目章程

**需求陈述**：项目立项生成项目章程，明确目标、范围、交付物、关键干系人、预算/资源、里程碑、风险与验收标准。

**验收标准**：

- **AC-1** `project_charter` 含项目名称、背景、目标、范围（含不做什么）、交付物、干系人、预算、资源、里程碑、风险、验收标准、发起人/负责人。
- **AC-2** 章程必须关联客户/合同/商机（如适用）与公司目标（OKR）；无关联时标注“内部项目”。
- **AC-3** 章程批准前项目状态为“立项中”，不得产生执行类写入；批准后生成项目编号与基线草案。
- **AC-4** 章程变更走变更单，不覆盖原版本；历史版本可查。

追溯：AC 直验

### 3.3 REQ-PRJ-003 范围、交付物与 WBS 联动

**需求陈述**：项目范围以交付物清单表达，并与 WBS 员工的工作分解、工作包、验收标准联动；范围变更同步影响 WBS 与计划。

**验收标准**：

- **AC-1** `project_scope` 含交付物、验收标准、责任人、关联 WBS 节点、版本与状态。
- **AC-2** 交付物必须映射到至少一个 WBS 工作包；未映射项提示补全。
- **AC-3** 范围变更生成 `project_change`，评估对里程碑、任务、成本、OKR 的影响；未批准不改变基线。
- **AC-4** 范围蔓延检测：新增交付物未走变更、任务超出原范围时提示，不静默纳入。

追溯：AC 直验 / WBS 员工联动

### 3.4 REQ-PRJ-004 里程碑管理

**需求陈述**：按项目阶段与关键交付设置里程碑，里程碑有目标日期、实际日期、准入/退出条件、责任人、依赖与状态。

**验收标准**：

- **AC-1** `milestone` 含名称、阶段、目标日期、实际日期、状态（未开始/进行中/已达成/延期/取消）、责任人、依赖、验收证据。
- **AC-2** 里程碑延期或提前需记录原因与影响；不自动改目标日期。
- **AC-3** 里程碑达成必须有证据（交付物、验收记录、会议纪要、客户确认）；无证据只能标“待核实”。
- **AC-4** 里程碑风险（临近未完成、依赖未满足）进入聚合提醒；影响截止日的即时提醒。
- **AC-5** 里程碑与 OKR 关键结果可关联；达成状态回卷到 OKR，但需标注来源与时间。

追溯：AC 直验

### 3.5 REQ-PRJ-005 细化任务、依赖与资源排期

**需求陈述**：把工作包细化为可执行任务，定义工期、依赖、负责人、资源、优先级、验收标准；支持串行/并行、前置/后置、里程碑依赖。

**验收标准**：

- **AC-1** `task` 含任务编号、名称、所属项目/工作包/里程碑、负责人、开始/结束、工期、进度、优先级、状态、验收标准。
- **AC-2** `task_dependency` 支持 FS/SS/FF/SF 依赖与滞后/提前量；依赖成环必须拒绝。
- **AC-3** 资源分配含人员/角色、可用容量、分配工时；超配或冲突提示，不自动压工期。
- **AC-4** 任务变更（负责人、日期、依赖、范围）写审计并提示受影响任务/里程碑。
- **AC-5** 任务进度更新需证据或确认；批量更新不得覆盖已验收任务。

追溯：AC 直验 / `project_plan_baseline` 流程

### 3.6 REQ-PRJ-006 甘特图、基线、关键路径与偏差

**需求陈述**：提供甘特图视图，展示任务/里程碑/依赖/基线 vs 实际/关键路径；支持缩放、筛选、下钻与导出。

**验收标准**：

- **AC-1** 甘特图按时间轴展示任务、里程碑、依赖箭头、基线条与实绩条；支持日/周/月视图。
- **AC-2** 关键路径自动计算并可高亮；关键路径变化提示影响与原因。
- **AC-3** 基线快照保存范围、日期、依赖、成本；基线 vs 实际偏差按任务/里程碑/项目汇总。
- **AC-4** 甘特图只读展示，不通过拖拽直接改基线；调整必须走任务变更/基线变更流程。
- **AC-5** 甘特图导出 PNG/PDF/CSV，附数据截止时间与口径版本。

追溯：AC 直验

### 3.7 REQ-PRJ-007 进度跟踪、偏差与挣值分析

**需求陈述**：按任务/里程碑/项目汇总进度，计算计划价值、挣值、实际成本、进度偏差、成本偏差与完工预测；偏差超阈值提示。

**验收标准**：

- **AC-1** 进度汇总口径统一（工时/权重/交付物），不同视图不出现两套数字。
- **AC-2** 支持 PV/EV/AC、SV/CV、SPI/CPI、EAC/ETC 计算；假设与口径可查。
- **AC-3** 偏差超阈值（可配）进入聚合提醒；影响里程碑/截止日的即时提醒。
- **AC-4** 成本数据来自财税汇总；明细经 `need_detail`，不在项目侧另建第二套成本账。
- **AC-5** 预测标注区间与假设，不把预测写成确定值。

追溯：AC 直验 / 财税联动

### 3.8 REQ-PRJ-008 目标管理（OKR）联动

**需求陈述**：项目目标、里程碑、关键交付与公司 OKR/关键结果对齐；项目进度回卷到 OKR，但需标注来源与口径，避免重复计算。

**验收标准**：

- **AC-1** `okr_link` 含项目、目标、关键结果、权重、贡献口径、来源、更新时间。
- **AC-2** 项目/里程碑进度可按权重回卷到 OKR；冻结/冲突数据按“含冻结 + 脚注”口径。
- **AC-3** 一个项目可关联多个 OKR，但同一关键结果的贡献权重合计不得超过 100%；超额提示。
- **AC-4** OKR 进度变化保留历史快照与来源；不静默覆盖人工调整。
- **AC-5** 项目风险影响 OKR 时提示，不替老板调整目标。

追溯：AC 直验 / 战略参谋联动

### 3.9 REQ-PRJ-009 风险、问题与变更管理

**需求陈述**：维护风险登记册、问题清单与变更单；评估影响、责任人、期限、应对措施与状态；重大变更走 human gate。

**验收标准**：

- **AC-1** `risk_issue` 含类型（风险/问题）、描述、概率/影响、等级、责任人、应对措施、期限、状态、关联任务/里程碑。
- **AC-2** 变更单含变更内容、原因、影响（范围/进度/成本/质量/OKR）、备选方案、审批人与结论。
- **AC-3** 高风险/重大变更必须老板确认；未批准变更不改变基线。
- **AC-4** 风险转问题、问题关闭、变更实施均留痕并更新项目状态。
- **AC-5** 风险矩阵与阈值可配置；不把“未识别”写成“无风险”。

追溯：AC 直验 / 冲突冻结与裁决

### 3.10 REQ-PRJ-010 质量、交付物与验收管理

**需求陈述**：管理交付物清单、质量标准、评审记录、缺陷/整改与验收；验收终审为 human gate，验收后联动开票/回款。

**验收标准**：

- **AC-1** `acceptance` 含交付物、验收标准、验收人、验收日期、结论、缺陷/整改项、证据。
- **AC-2** 交付物必须关联版本与评审记录；未评审/未整改不得进入验收。
- **AC-3** 验收终审 `human_gate` 且 `timeout_policy=hold`；超时保持挂起并按截止日逐级提醒。
- **AC-4** 验收通过后可触发开票/回款跟踪；状态迁移写审计，不自动开票。
- **AC-5** 验收驳回生成整改任务并关联原验收记录，不删除历史。

追溯：UC-006（Verifier 侧）/ `project_acceptance_flow`

### 3.11 REQ-PRJ-011 干系人、沟通与状态报告

**需求陈述**：维护干系人、沟通计划与项目状态报告；按频率生成周报/月报，附进度、风险、变更、成本、验收与下一步。

**验收标准**：

- **AC-1** `status_report` 含期间、项目状态、里程碑、任务完成、偏差、风险/问题、变更、成本、验收、下一步。
- **AC-2** 干系人含角色、关注点、沟通频率、渠道、权限；敏感信息按视图/令牌控制。
- **AC-3** 状态报告数据带 `as_of` 与来源；冻结数据加脚注。
- **AC-4** 报告可导出/推送，但不替代正式验收或合同通知。
- **AC-5** 重大风险/延期即时提醒，不等周报。

追溯：AC 直验

### 3.12 REQ-PRJ-012 成本、合同与回款联动

**需求陈述**：项目预算/成本/合同/开票/回款与财税、法务、客户管家联动；成本异常经 `need_detail` 获取明细，不另建账。

**验收标准**：

- **AC-1** 项目预算与合同金额、WBS 成本估算、实际成本可对照；差异列明原因。
- **AC-2** 验收—开票—回款状态与财税口径一致；不出现项目侧与财务侧两套状态。
- **AC-3** 成本汇总异常时发起 `need_detail` 二次派工，请求方上下文不落明细。
- **AC-4** 回款逾期/合同到期进入项目风险与提醒。
- **AC-5** 项目毛利/客户盈利只呈报事实与敏感性，不输出取舍结论。

追溯：UC-006 / AC 直验

### 3.13 REQ-PRJ-013 收尾、复盘与知识沉淀

**需求陈述**：项目收尾完成交付物归档、合同/财务结算、资源释放、经验教训与复盘；复盘结论进入经验库/技能库。

**验收标准**：

- **AC-1** `project_closure` 含收尾清单、交付物归档、合同结算、财务结算、资源释放、遗留问题、复盘结论。
- **AC-2** 未完成验收/回款/合同结算的项目不得标记“已关闭”，只能标“收尾中”。
- **AC-3** 复盘输出“触发条件→现象→根因→下次动作”卡片，老板确认后写入经验库。
- **AC-4** 可复用模板/检查清单进入技能库/模板库，附来源项目与版本。
- **AC-5** 收尾后项目数据只读保留，后续变更走新项目或变更单。

追溯：AC 直验 / `project_closure` 流程

### 3.14 REQ-PRJ-014 标准化模板、RACI 与项目治理

**需求陈述**：按项目类型提供标准模板（章程、计划、WBS、里程碑、任务、风险、验收、收尾、报告）与 RACI/职责分离；模板变更版本化。

**验收标准**：

- **AC-1** 模板含阶段、交付物、里程碑、任务清单、角色与审批点；新建项目可选择模板。
- **AC-2** RACI 明确负责/批准/咨询/知会；关键节点不得由同一人既执行又终审（单老板场景显式提示补偿控制）。
- **AC-3** 模板/流程变更版本化，历史项目保留原版本；升级不覆盖运行中项目。
- **AC-4** 项目治理指标（阶段门通过率、延期率、变更率、验收一次通过率）可统计。
- **AC-5** 模板与公司目标/经营范围匹配；不适用时提示裁剪。

追溯：AC 直验

### 3.15 REQ-PRJ-015 权限、审计与降级

**需求陈述**：项目数据按角色/视图授权；全流程审计；外部依赖不可用时显式降级，不伪造进度/成本/验收。

**验收标准**：

- **AC-1** 项目、任务、成本、客户/合同敏感信息按视图与角色控制；跨域明细走 `need_detail`/令牌。
- **AC-2** 立项、阶段门、计划/基线、任务变更、风险/变更、验收、收尾、导出均写审计。
- **AC-3** 财税/合同/客户/OKR 数据不可用时标注“数据不足/未获取”，不猜测填充。
- **AC-4** 停用项目监理后不再派工、工具不可见、流程不启动；项目数据只读保留。
- **AC-5** 删除/归档项目必须老板确认并写数据删除审计；已归档项目只追加不覆盖。

追溯：AC 直验 / 主 SRS §7 审计

### 3.16 REQ-PRJ-016 软件研发项目档案与项目起点

**需求陈述**：为软件研发类项目提供专用档案，明确项目起点（立项批准、计划基线冻结、启动会）与研发要素（技术栈、代码库、制品库、环境、测试策略），与通用项目共用生命周期但增加研发检查项。

**验收标准**：

- **AC-1** `project` 支持 `project_type=software`，含 `start_date`（项目起点）、`target_end_date`、`actual_start_date`、`actual_end_date`、`timezone`、`work_calendar`、`tech_stack`、`software_profile`。
- **AC-2** 项目起点必须明确三项之一并留痕：章程批准日、计划基线冻结日、启动会日期；未确定起点不得生成进度基线。
- **AC-3** 软件项目必须声明代码库、制品库、环境清单与测试策略；缺失项在阶段门提示“研发要素不完整”，不阻断只读查看。
- **AC-4** 研发要素变更（技术栈、仓库、环境、测试策略）走变更单，记录影响范围；未批准不改变已冻结基线。
- **AC-5** 项目起点、关键节点与时间口径写入项目档案，对外报告统一引用同一口径，不出现两套日期。

追溯：AC 直验 / `project_stage_gate` 流程

### 3.17 REQ-PRJ-017 版本库管理（Git / SVN）

**需求陈述**：统一登记项目使用的 Git/SVN 版本库地址、协议、默认分支/主干、认证引用与同步策略；只同步元数据（分支、标签、提交/修订），不在中枢保存代码副本。

**验收标准**：

- **AC-1** `code_repository` 含项目、名称、类型（`git`/`svn`）、地址、默认分支（Git）或主干路径（SVN）、认证引用 `auth_ref`、同步方式（手动/定时/Webhook）、同步状态与最近同步时间。
- **AC-2** 凭据只以 `auth_ref` 引用密钥/环境变量，禁止明文入库、禁止写入日志与员工包；导出员工包默认不含凭据。
- **AC-3** 元数据同步只读：Git 读取分支、标签、提交 SHA、作者与时间；SVN 读取 trunk/branches/tags、修订号、作者与时间；同步失败标注“未同步/数据不可用”，不编造提交记录。
- **AC-4** 支持将提交/修订关联到任务、里程碑与发布单；关联需记录来源与时间，不自动修改任务状态。
- **AC-5** 仓库地址或认证变更必须写审计；停用仓库不删除历史关联，只停止同步。

追溯：AC 直验 / `project_release_flow` 流程

### 3.18 REQ-PRJ-018 制品仓库管理（Maven / Docker）

**需求陈述**：统一登记 Maven、Docker 等制品仓库与制品坐标，支持查询可用版本、镜像标签与摘要；发布/推送必须经发布单与审批，默认不自动推送。

**验收标准**：

- **AC-1** `artifact_repository` 含项目、类型（`maven`/`docker`/其他）、仓库地址、命名空间、认证引用 `auth_ref`、保留策略、状态；凭据同样只存引用。
- **AC-2** Maven 制品记录 `groupId:artifactId:version` 与校验和；Docker 镜像记录 `repository:tag@digest`，以 digest 作为不可变标识，tag 仅作展示。
- **AC-3** 查询制品/镜像列表只读；拉取与推送按仓库权限控制，生产仓库推送必须有发布单与老板确认，不得设置自动默认。
- **AC-4** 制品与发布单、版本库标签、测试报告关联；缺少摘要或校验和的制品标记“证据不完整”。
- **AC-5** 保留策略只影响查询展示与清理建议，不自动删除制品；删除必须人工确认并写审计。

追溯：AC 直验 / `project_release_flow` 流程

### 3.19 REQ-PRJ-019 部署环境与 SSH 发布

**需求陈述**：管理开发、测试、预发、生产等部署环境，登记 SSH 主机与认证引用；发布单驱动部署、健康检查与回滚，生产发布必须 human gate。

**验收标准**：

- **AC-1** `deploy_environment` 含项目、环境类型（`dev`/`test`/`staging`/`prod`）、名称、主机、端口、SSH 用户、认证引用、跳板机引用（可选）、隔离级别、审批策略与状态。
- **AC-2** 凭据只存 `auth_ref`；SSH 必须校验主机指纹，禁止 `StrictHostKeyChecking=no`；可执行命令按环境白名单/模板限制，禁止任意命令透传。
- **AC-3** `release_order` 含版本、制品引用、目标环境、变更说明、回滚版本、申请人、审批人、执行状态与时间；同一环境同一时刻只允许一个执行中的发布。
- **AC-4** 开发/测试环境可按策略自动执行；预发/生产必须老板或授权人确认，`timeout_policy=hold`，不可逆动作不得设自动默认；发布后必须健康检查并留存日志摘要。
- **AC-5** 支持回滚到指定版本；回滚同样走发布单与审批；部署、回滚、审批、失败原因全部写审计，敏感值不入日志。

追溯：AC 直验 / `project_release_flow` 流程

### 3.20 REQ-PRJ-020 测试统一管理

**需求陈述**：按项目/版本统一管理测试计划、用例、套件、执行、结果与缺陷；覆盖手工与自动化测试，关联需求、里程碑、发布单与环境，形成可追溯的测试证据链。

**验收标准**：

- **AC-1** `test_plan` 含项目、版本/迭代、范围、测试类型（单元/集成/接口/UI/性能/安全/验收）、进入/退出标准、环境、负责人、起止时间与状态。
- **AC-2** `test_case` 含用例编号、标题、前置条件、步骤、预期结果、优先级、类型（手工/自动）、关联需求/验收标准；用例变更保留版本。
- **AC-3** `test_suite` 组织用例集合；`test_run` 记录执行批次、环境、版本、执行人/Agent、开始结束时间；`test_result` 记录逐用例结果、证据与失败原因。
- **AC-4** `defect` 含严重级别、复现步骤、影响版本、关联用例/需求、责任人、状态与回归结果；缺陷关闭必须有验证证据。
- **AC-5** 测试执行不得伪造结果；环境不可用或用例未执行标注“未执行/阻塞”，不以通过计；测试数据须脱敏或使用专用测试数据。

追溯：AC 直验 / `project_test_review` 流程

### 3.21 REQ-PRJ-021 专门测试 Agent 协同

**需求陈述**：设立专门测试 Agent，按项目需求生成测试策略与用例、执行自动化测试、归类失败、输出测试报告；Agent 只提供证据与建议，不替代老板做发布/验收终审。

**验收标准**：

- **AC-1** 测试 Agent 以独立角色卡部署（经 `dsh-super-agents`），绑定项目与测试计划；具备测试计划、用例、执行、缺陷、报告工具，不授予生产写权限。
- **AC-2** 用例生成必须引用需求/验收标准与来源；无来源的推断用例标记“建议用例”，不得冒充已批准用例。
- **AC-3** 自动化执行默认只在 `dev`/`test` 环境；对 `staging`/`prod` 的只读冒烟需单独授权，禁止执行写操作与数据修改。
- **AC-4** 失败归类区分“产品缺陷/用例问题/环境问题/数据问题”，置信度低时升级人工；不把未复现失败直接判为通过。
- **AC-5** 测试报告含范围、环境、版本、通过/失败/阻塞数、缺陷清单、覆盖率、未覆盖风险与 `as_of`；发布/验收结论由老板确认，Agent 不自动放行。

追溯：AC 直验 / `project_test_review` 流程

### 3.22 REQ-PRJ-022 时间管理、日历与关键节点

**需求陈述**：以项目起点为锚，维护工作日历、时区、计划/实际日期、关键节点与里程碑，支持工期、浮动时间、关键路径与到期提醒；时间变更留痕，不静默改期。

**验收标准**：

- **AC-1** 项目含 `timezone` 与 `work_calendar`（工作日、节假日、每日工时）；跨时区项目统一按项目时区计算，报告标注口径。
- **AC-2** 关键节点/里程碑含目标日期、实际日期、依赖、责任人与准入/退出条件；关键节点延期必须记录原因与影响。
- **AC-3** 任务支持工期、开始/结束、浮动时间与关键路径；日期变更写审计并提示受影响的任务、里程碑与发布单。
- **AC-4** `work_log` 记录工时（人、日期、任务、时长、来源）；工时仅作事实记录，不自动折算绩效。
- **AC-5** 到期提醒按提前量分级（如 7/3/1 天），影响里程碑或发布截止日的即时提醒；提醒不替代正式审批。

追溯：AC 直验 / `project_status_review` 流程

## 4. 数据对象与视图（需求层）

| 数据对象 | 用途 |
| :--- | :--- |
| `project` | 项目主档：类型、生命周期阶段、状态、负责人、日期 |
| `project_charter` | 项目章程：目标、范围、交付物、干系人、预算、风险、验收标准 |
| `project_plan` | 项目计划：阶段、计划版本、审批状态 |
| `milestone` | 里程碑：目标/实际日期、状态、依赖、验收证据 |
| `task` / `task_dependency` | 细化任务与 FS/SS/FF/SF 依赖、资源分配 |
| `project_baseline` | 范围/进度/成本基线快照与版本 |
| `project_change` | 范围/进度/成本/质量变更单与审批 |
| `risk_issue` | 风险登记册与问题清单 |
| `status_report` | 周报/月报/状态报告与 `as_of` |
| `acceptance` | 交付物验收、缺陷整改与证据 |
| `project_closure` | 收尾清单、结算、复盘与知识沉淀 |
| `okr_link` | 项目/里程碑与 OKR/关键结果的权重与回卷口径 |
| `work_log` | 工时记录：人、日期、任务、时长、来源 |
| `code_repository` | Git/SVN 版本库地址、分支/主干、认证引用与同步状态 |
| `artifact_repository` | Maven/Docker 仓库地址、命名空间、认证引用与保留策略 |
| `deploy_environment` | 开发/测试/预发/生产环境、SSH 主机、认证引用与审批策略 |
| `release_order` | 发布单：版本、制品、目标环境、审批、回滚与执行结果 |
| `test_plan` / `test_case` / `test_suite` | 测试计划、用例与套件 |
| `test_run` / `test_result` / `defect` | 测试执行批次、逐用例结果与缺陷 |

**视图**：公司档案、项目状态、应收应付、合同索引、OKR、客户基础信息只读；客户敏感字段不进入项目视图；跨域明细经 `need_detail` 或一次性令牌。

## 5. 事件、降级与审计

- **主动事件**：阶段门待审、里程碑临近/延期、任务逾期、关键路径变化、进度/成本偏差超阈值、OKR 风险、范围蔓延、重大变更、验收待审/驳回、回款逾期、项目收尾；版本库同步失败、制品证据不完整、发布待审、生产发布失败、回滚、测试阻塞/失败率超阈值、测试报告待确认。
- **降级**：财税/合同/客户/OKR/版本库/制品库/SSH 环境/测试环境不可用时标注“数据不足/未获取/未执行”，不伪造进度、成本、验收、提交记录、制品摘要、发布结果或测试结果。
- **审计**：立项、阶段门、计划/基线、任务变更、风险/变更、验收、收尾、报告导出、删除归档；版本库/制品库地址与认证变更、发布/回滚/审批、测试计划与用例变更、测试执行与缺陷关闭均入审计。
