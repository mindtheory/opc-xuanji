# 情报官 员工需求规格说明

## 1. 定位与边界

情报官覆盖行业/政策监测、竞争对手、线索商机、交易对手尽调、供应商风险、市场舆情、**项目化情报日报**、信息源管理与关键词/标签订阅；是老板的外部雷达。日报流水线按“采集 → 分析 → 汇总 → 简报 → 推送”自动运行，每个项目拥有独立的关键词、标签、数据源与推送设置。

参考国内同类软件（用友/金蝶/钉钉/飞书/企微/销售易/纷享销客/管家婆/聚水潭/合同管理系统等）的通用功能，按中国业内标准与通用职位工作内容整理；固定步骤由工作流完成，需要理解与判断的由 AI 完成，取舍与责任仍归老板。

**边界**：
- 不把未验证信息写成事实；来源、时间、覆盖度必须标注。
- 尽调报告不构成法律/投资意见；重大合作提示律师/财务复核。
- 不采集个人隐私或违反授权/版权的内容。
- MCP/外部源不可用时标注“未获取/风险未知”，不猜测。

## 3. 功能需求

### 3.1 REQ-INT-001 行业与政策监测

**需求陈述**：监测行业趋势、政策法规、补贴/资质、监管变化；附来源与生效期。

**验收标准**：

- **AC-1** 条目含来源、发布时间、适用范围、可信度。
- **AC-2** 政策变化提示影响合同/财税/业务。
- **AC-3** 非官方来源只标“疑似”。

追溯：AC 直验

### 3.2 REQ-INT-002 竞争对手监测

**需求陈述**：跟踪竞品产品、价格、渠道、营销、融资与动态。

**验收标准**：

- **AC-1** 竞品档案与动态时间线。
- **AC-2** 对比只呈报事实，不贬损。
- **AC-3** 来源与时间可查。

追溯：AC 直验

### 3.3 REQ-INT-003 线索与商机挖掘

**需求陈述**：按行业/区域/关键词发现线索，评分、去重、分配与跟进。

**验收标准**：

- **AC-1** 线索含来源、联系方式合规性、评分依据。
- **AC-2** 高意向线索聚合提醒。
- **AC-3** 不抓取隐私/违规数据。

追溯：AC 直验

### 3.4 REQ-INT-004 交易对手尽调

**需求陈述**：对客户/供应商/合作方做工商、司法、信用、舆情、关联关系尽调。

**验收标准**：

- **AC-1** 报告含数据源、查询时间、已知盲区、免责声明。
- **AC-2** 查到风险/查无记录/源不可用三级措辞。
- **AC-3** 不构成投资/法律意见。

追溯：AC 直验

### 3.5 REQ-INT-005 供应商风险

**需求陈述**：供应商资质、履约、财务、诉讼、舆情、集中度风险。

**验收标准**：

- **AC-1** 风险等级/来源/时间可查。
- **AC-2** 风险提示备选供应商，不替老板选择。
- **AC-3** 重大风险即时提醒。

追溯：AC 直验

### 3.6 REQ-INT-006 市场与客户舆情

**需求陈述**：监测品牌、客户、行业负面/正面舆情与传播节点。

**验收标准**：

- **AC-1** 舆情含来源、时间、情绪、影响范围。
- **AC-2** 负面舆情即时提醒并转外宣/法务。
- **AC-3** 不删除/不操控舆论。

追溯：AC 直验

### 3.7 REQ-INT-007 情报简报与专题报告

**需求陈述**：按日/周/月生成简报与专题报告，附来源、结论与不确定性。

**验收标准**：

- **AC-1** 简报含要点、来源、影响、建议关注。
- **AC-2** 专题报告含方法、数据、局限。
- **AC-3** 不把推测写成事实。

追溯：AC 直验

### 3.8 REQ-INT-008 信息源管理与验证

**需求陈述**：维护来源白名单/黑名单、可信度、授权与更新频率。

**验收标准**：

- **AC-1** 来源含类型、可信度、授权、最近验证时间。
- **AC-2** 低可信来源降权/标注。
- **AC-3** 版权/授权不合规来源不采集。

追溯：AC 直验

### 3.9 REQ-INT-009 关键词/主题订阅

**需求陈述**：按公司发展关键词、客户、竞品、政策主题订阅与去重。

**验收标准**：

- **AC-1** 关键词可配置、分组、优先级。
- **AC-2** 命中去重、聚合、附来源。
- **AC-3** 未检索时标注“本次未检索”。

追溯：AC 直验

### 3.10 REQ-INT-010 情报归档与合规

**需求陈述**：情报条目/报告按保留期归档，来源可追溯，敏感信息受控。

**验收标准**：

- **AC-1** 归档带哈希、来源、版本。
- **AC-2** 导出/删除审批与审计。
- **AC-3** 个人隐私/商业秘密按权限。

追溯：AC 直验

### 3.11 REQ-INT-011 项目化情报空间

**需求陈述**：按项目划分情报空间；每个项目独立配置时区、日报时间、回看窗口、条数上限、推送渠道、模板与启停，数据源/关键词/标签/条目/简报/推送均带项目归属。

**验收标准**：

- **AC-1** `intel_project_scope` 含项目、名称、时区、`brief_time`、回看小时、条数上限、推送渠道、接收人、静默时段、模板、状态与配置版本；同一项目只允许一个有效空间。
- **AC-2** 查询、分析、简报与推送默认按 `project_id` 隔离；跨项目复用数据源必须显式建立 `source_binding`，不得读取其他项目的关键词、标签或简报。
- **AC-3** 项目停用后停止采集与推送，历史条目/简报只读保留；重新启用不补推历史，除非老板手动重跑。
- **AC-4** 配置变更写审计并递增 `config_version`；变更生效前已生成的简报不被改写。
- **AC-5** 老板或授权人可按项目查看最近采集、分析、简报、推送状态与覆盖度。

追溯：AC 直验 / `intel_daily_pipeline`

### 3.12 REQ-INT-012 采集数据源注册与健康管理

**需求陈述**：统一登记采集数据源（RSS/API/网页/搜索/MCP/人工），管理认证引用、可信度、版权授权、采集间隔、限流、超时、启停与健康状态。

**验收标准**：

- **AC-1** `source` 含名称、类型、地址、`auth_ref`、可信度（0–1）、版权状态、授权说明、采集间隔（5 分钟–7 天）、限流（次/小时）、超时、启停与状态。
- **AC-2** 凭据只存 `auth_ref` 引用，禁止明文入库、写日志或随员工包导出；导出默认不含凭据。
- **AC-3** 每次采集写 `intel_collect_run`：来源、项目、开始/结束、状态、抓取/新增/去重/失败数、HTTP 状态、耗时、错误与 checkpoint。
- **AC-4** 连续失败达到阈值（默认 3 次）自动标 `blocked` 并即时提醒；恢复后需人工或下一次成功采集解除，不静默重试。
- **AC-5** 来源不可用、授权失效或超时标 `blocked`/`failed`，不以 0 冒充“无数据”；版权不合规来源不采集。

追溯：AC 直验 / `intel_source_collect`

### 3.13 REQ-INT-013 项目关键词与标签规则

**需求陈述**：每个项目维护独立的关键词与标签规则，支持精确/短语/正则/布尔匹配、同义词、排除词、优先级与版本化；标签支持分类与层级。

**验收标准**：

- **AC-1** `watch_topic` 含项目、关键词、匹配类型、同义词、排除词、标签、优先级、启停与版本；变更递增版本并留痕。
- **AC-2** `intel_tag` 按项目维护名称、分类、父标签、颜色与说明；同项目标签名唯一，条目可多标签。
- **AC-3** 分析结果输出命中关键词、命中标签、排除词、分值（0–100）与理由；排除词命中条目标 `filtered`，不进入该项目日报。
- **AC-4** 同一条目命中多个项目时按各自规则分别评分；不得把 A 项目的关键词/标签用于 B 项目。
- **AC-5** 未配置关键词与标签时按“仅来源订阅”运行并在简报标注“未命中规则”，不伪造相关性。

追溯：AC 直验 / `intel_analyze`

### 3.14 REQ-INT-014 定时采集与增量幂等

**需求陈述**：调度器按来源间隔、限流与超时自动采集，支持手动/强制重跑；以来源外部 ID 或内容哈希幂等，失败从 checkpoint 续采。

**验收标准**：

- **AC-1** 采集任务按 `collect_interval_minutes` 判断到期来源；同一来源在同一时间槽只执行一次，重复触发跳过。
- **AC-2** 条目以 `(project_id, idempotency_key)` 唯一，`idempotency_key` 优先取 `source_id + external_id`，缺失时取内容哈希；重复采集不重复入库。
- **AC-3** 单个来源失败不影响其他来源；失败写 `intel_collect_run` 并告警，未配置适配器标 `blocked` 和“本次未采集”。
- **AC-4** 采集只写原始条目（`collected`），不直接生成结论；缺标题或既无来源又无 URL 的条目不进入后续阶段。
- **AC-5** 未配置任何来源时返回“本次未采集”，不生成虚构条目、不把空采写成成功覆盖。

追溯：AC 直验 / `intel_source_collect`

### 3.15 REQ-INT-015 情报分析、去重与评分

**需求陈述**：对采集条目做归一化、去重、关键词/标签命中、相关性评分、情绪与信息类型标注，输出可追溯的分析结果。

**验收标准**：

- **AC-1** 归一化标题、摘要、来源、发布时间与作者；按 URL、内容哈希与近似标题去重，保留主条目与重复来源计数。
- **AC-2** 输出相关性分值、命中关键词/标签、排除词、情绪、信息类型（事实/推断/传闻/未知）、风险等级、可信度与摘要。
- **AC-3** 事实、推断、传闻必须区分；缺证据时标 `unknown` 或“数据不足”，不得把推断写成事实。
- **AC-4** 分析失败条目保持 `collected` 或标 `failed`，不进入简报；可重跑且不重复生成。
- **AC-5** 分析结果记录规则/模型版本与输入条目 ID，可追溯到当时规则。

追溯：AC 直验 / `intel_analyze`

### 3.16 REQ-INT-016 汇总与情报日报生成

**需求陈述**：按项目在本地 `brief_time` 生成日报或周报，按主题分区汇总，附来源、时间、影响与覆盖度声明；简报版本化，可人工复核。

**验收标准**：

- **AC-1** `intel_brief` 含项目、日期、类型（日报/周报）、标题、状态、覆盖度、分区内容、条目 ID、来源数、条目数、生成时间与版本。
- **AC-2** 固定分区：今日必看、政策/监管、竞品、线索/商机、供应商/交易对手风险、舆情、其他；每区按分值排序，附来源、发布时间、摘要与影响。
- **AC-3** 覆盖度声明含回看窗口、来源数、采集成功/失败/阻塞、分析/过滤/去重条数、未检索项与空采项目。
- **AC-4** 无合格条目的项目生成“本期无新增”空白简报并说明缺口，不省略、不虚构。
- **AC-5** 同日重跑生成新版本，不覆盖已推送版本；已推送简报只读保留。

追溯：AC 直验 / `intel_brief`

### 3.17 REQ-INT-017 简报推送与送达追踪

**需求陈述**：按项目配置推送渠道、接收人、优先级阈值与静默时段；每次推送留痕，外部渠道不可用时降级站内，不静默失败。

**验收标准**：

- **AC-1** 推送渠道支持站内、邮件、IM/Webhook 等；接收人/角色、优先级阈值与静默时段按项目配置。
- **AC-2** 22:00–08:00 非紧急不推送；截止日 12 小时内或高风险/负面舆情可即时推送，普通条目进日报。
- **AC-3** 每次推送写 `intel_push_log`：简报、项目、渠道、对象、状态、尝试次数、发送/确认时间与错误；同一简报同一渠道同一对象不重复推送。
- **AC-4** 推送内容必须含来源与发布时间；无来源条目不推送。
- **AC-5** 外部渠道未配置或失败时降级为站内待办，标注“外部渠道未送达”，并产生告警；不把未送达写成已送达。

追溯：AC 直验 / `intel_push`

### 3.18 REQ-INT-018 流水线编排与运行监控

**需求陈述**：按项目编排“采集→分析→汇总→简报→推送”五阶段；各阶段独立定时、幂等、可重跑，前置未完成时下游等待或跳过并记录原因。

**验收标准**：

- **AC-1** 五阶段均有独立任务与运行记录；采集按来源间隔，分析按小时，汇总/简报/推送按项目本地时间到点。
- **AC-2** 每次运行写 `intel_pipeline_run`（项目、日期、阶段、状态、开始/结束、计数、错误、幂等键）；同一幂等键重复触发跳过。
- **AC-3** 阶段失败/超时重试有上限；部分成功标 `partial`，不把部分成功当全部成功。
- **AC-4** 驾驶舱可查看各项目最近一次运行状态、耗时、覆盖度与失败原因；支持按阶段手动重跑。
- **AC-5** 任务执行、重跑、配置变更与推送均写审计，审计不落凭据与未授权原文。

追溯：AC 直验 / `intel_daily_pipeline`

## 4. 数据对象与视图（需求层）

| 数据对象 | 用途 |
| :--- | :--- |
| `intel_project_scope` | 项目情报空间（时区、日报时间、回看窗口、渠道） |
| `source` | 采集数据源、认证引用、可信度与健康状态 |
| `source_binding` | 数据源与项目的多对多绑定 |
| `watch_topic` | 项目关键词规则（匹配、同义词、排除词、优先级） |
| `intel_tag` | 项目标签字典（分类、层级、说明） |
| `intel_item` | 行业/政策/竞品/舆情原始与分析后条目 |
| `intel_collect_run` | 单次采集运行与 checkpoint |
| `intel_brief` | 项目日报/周报（版本化） |
| `intel_pipeline_run` | 五阶段流水线运行记录 |
| `intel_push_log` | 推送渠道、对象、状态与错误 |
| `lead` | 线索/商机 |
| `dd_report` | 尽调报告与覆盖度声明 |
| `supplier_risk` | 供应商风险 |

**视图**：客户/项目/合同只读；敏感客户信息不进入情报视图；外部数据标注来源与时间。

## 5. 事件、降级与审计

- **主动事件**：政策/法规更新、竞品动作、高意向线索、供应商风险、负面舆情、关键词/标签命中、采集失败/熔断、日报生成、推送未送达、尽调到期。
- **降级**：外部数据/接口不可用时标注“未获取/需人工/数据不足”；采集来源不可用标 `blocked`；外部推送渠道未配置时降级站内并标“外部渠道未送达”；不猜测、不伪造、不静默失败。
