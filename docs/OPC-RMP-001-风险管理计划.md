# OPC-玄机 · 一人公司中枢 风险管理计划（OPC-RMP-001）

本文解决“这个项目最可能在哪里翻车、怎么提前发现、翻车后怎么兜底”的问题。风险不是列一张吓人的表，而是**每条都有触发信号、责任人、应对动作和兜底方案**。使用者与时机：老板在月度复盘看 P0/P1 风险；项目集成者在周报更新状态；开发在设计与测试时按“预防措施”执行；评审在 G0/G6 检查风险是否被承认而不是被隐藏。本文的风险来源包括产品设计“残余风险”、`OPC-STR-001` 的未覆盖项、`OPC-SDD-001` 的 Phase 2 清单与当前部署事实。

## 1. 目的与方法

### 1.1 目的

- 提前识别会影响**交付、资金、合规、老板注意力**的风险。
- 把“已知但未解决”的能力明确标为风险，而不是伪装成已实现。
- 为每条高风险准备可执行的兜底，避免出事时临时拍脑袋。

### 1.2 方法

1. **识别**：从产品设计残余风险、测试未覆盖项、Phase 2 清单、部署事实、外部依赖中收集。
2. **评估**：按“概率 × 影响”评分，得到风险等级。
3. **应对**：规避、降低、转移、接受；每条写明触发信号与兜底。
4. **监控**：周报更新状态；月度复盘重评；季度全量复核。
5. **关闭**：风险消失或已转为问题并解决后关闭，保留记录。

## 2. 风险分级标准

### 2.1 概率（P）

| 分值 | 含义 | 判据 |
| :--- | :--- | :--- |
| 5 | 几乎确定 | 已经发生或必然发生 |
| 4 | 很可能 | 近期出现过，条件成熟 |
| 3 | 可能 | 有先例，条件部分具备 |
| 2 | 不太可能 | 有理论可能，条件不足 |
| 1 | 极少 | 仅极端情况 |

### 2.2 影响（I）

| 分值 | 影响 | 判据 |
| :--- | :--- | :--- |
| 5 | 灾难 | 资金/法律重大损失、数据泄露、无法交付 |
| 4 | 严重 | 发布延期、核心能力不可用、老板信任受损 |
| 3 | 中等 | 局部返工、性能下降、需人工兜底 |
| 2 | 轻微 | 体验下降、文档返工 |
| 1 | 可忽略 | 不影响目标 |

### 2.3 等级

| 分值（P×I） | 等级 | 处理 |
| :--- | :--- | :--- |
| 15–25 | P0 | 立即处理；老板知情；每周跟踪 |
| 8–14 | P1 | 本月处理；项目集成者负责 |
| 4–7 | P2 | 排期处理；季度复核 |
| 1–3 | P3 | 接受并记录 |

## 4. 重点风险应对

### 4.1 R-01 DSH 契约漂移（P0）

- **预防**：所有对 DSH 的调用集中在适配层；文档写“封装约定，非实际 API”；联调前先做契约核对清单。
- **发现**：联调失败、工具注册异常、路由 404、会话桥超时。
- **兜底**：独立 HTTP 服务仍可用；Web 面板降级为只读快照；在 SDD 10.2 登记偏差。
- **老板视角**：如果面板暂时不可用，老板仍能通过对话拿到结论；不会出现“系统全黑”。

### 4.2 R-02 Verifier 未接真实模型（P0）

- **预防**：接口先定，采样与评判分离；`Verifier.judge` 不伪造模型结论。
- **发现**：流程注册仍用测试 samples；测试报告未出现真实模型调用。
- **兜底**：高风险流程强制人工复核；Verifier 不可用时阻塞而不默认通过。
- **老板视角**：不会出现“系统说通过但其实没人校验”。

### 4.3 R-03 员工线未实现（P0）

- **预防**：需求、manifest、表结构先就绪；发布说明“已知限制”明确。
- **发现**：老板问某线功能为何不可用。
- **兜底**：按优先级分批；未上线员工明确标“Phase 2”；先用平台能力 + 人工。
- **老板视角**：能用的先说能用，不能用的不装作能用。

### 4.4 R-05 审计可篡改（P0）

- **预防**：代码只有 INSERT/SELECT；部署期另建 `opc_app` 角色仅 INSERT；`REVOKE UPDATE, DELETE`。
- **发现**：`verifyChain` 失败、导出哈希不匹配、账号权限过宽。
- **兜底**：每日导出 + SHA-256；链头持久化；异常即时告警。
- **老板视角**：审计不是“看起来有”，而是能证明没被改。

### 4.5 R-10 老板注意力过载（P1）

- **预防**：每日 ≤3 条主动推送；裁决卡 ≤1 屏；非紧急聚合；夜间静默。
- **发现**：老板不回、回复变慢、说“太长”。
- **兜底**：降级为“一条消息 + 一个按钮”；只留今天最要紧的 1 件事。
- **老板视角**：随时可以喊“停”，Agent 不会继续轰炸。

### 4.6 R-15 专业结论越界（P1）

- **预防**：税务/法律/投资结论固定标注“参考值/不构成专业意见”；来源与版本；重大事项建议复核。
- **发现**：老板直接按建议付款/签约/申报。
- **兜底**：不可逆动作强制确认；保留专业复核建议。
- **老板视角**：Agent 给的是决策材料，不是替老板签字。

## 5. 监控与报告

### 5.1 监控节奏

| 频率 | 动作 | 输出 |
| :--- | :--- | :--- |
| 每周 | 更新 P0/P1 风险状态、触发信号 | 周报“风险”一节 |
| 每月 | 重评概率/影响，关闭或升级 | 月度复盘 |
| 每季度 | 全量复核，新增/删除风险 | 风险登记表更新 |
| 事件后 | 新增风险或转问题 | PA 记录 |

### 5.2 报告格式（给老板）

```text
风险（1 条）：X 可能发生（概率/依据）。
影响：最坏情况是 Y。
兜底：我已经做了 Z，需要你决定是否 W。
```

只报**需要老板知道或拍板**的风险；技术细节进周报附件或 PA，不单独打扰。

### 5.3 升级规则

- P0 风险：24 小时内让老板知道；给 2–3 个应对选项与推荐。
- P1 风险：进入周报；本月内处理。
- 风险转为问题：按事故处理，先止损、再定位、再复盘、再补测试。
- 不可逆影响（资金/法律/数据）：立即停止相关动作，保留证据，老板拍板。

## 6. 风险与问题的边界

| 概念 | 定义 | 处理 |
| :--- | :--- | :--- |
| 风险 | 尚未发生、可能影响目标 | 预防、监控、兜底 |
| 问题 | 已发生、已造成影响 | 止损、修复、复盘、补测试 |
| 已知限制 | 设计上暂不支持、已登记 | 写入发布说明与 SDD 10.1，不当作缺陷 |

**硬规则**：已知限制不得伪装成“已实现”；风险不得因为“不想让老板担心”而隐藏。
