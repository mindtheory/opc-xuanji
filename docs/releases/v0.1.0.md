# OPC-玄机 · 一人公司中枢 v0.1.0

**Release date:** 2026-11-06  
**Status:** Initial release  
**Tag:** `v0.1.0`  
**Type:** DSH Bundle plugin + specification baseline

## Highlights

- **DSH Bundle plugin**: `opc-xuanji` with `cordis.patch.yml`, 31 `opc_*` tools, and 34 HTTP `/api/v1` operations.
- **Data layer**: PostgreSQL 17 + pgvector, 54 entities, 5 additive migrations (`0001`–`0005`).
- **Automation**: 10 scheduled tasks covering daily reports, tax/contract reminders, invoice backlog, conflict escalation, audit export, monthly archive, dashboard refresh, plugin radar, and keyword radar.
- **Web presentation layer**: sidebar entry, right-side dashboard, session/memory bridge, upload ingestion and confirmation, inbox, radar, and dashboard snapshot with `as_of`/stale/frozen footnotes.
- **Employee requirements**: 11 standalone documents (`docs/员工需求/OPC-SRS-101..111`) with 130 requirements covering finance, legal, admin, strategy, project, intel, CRM, vehicle, inventory, WBS, and publicity.
- **Pluggable employees**: manifests with views, tools, write targets, single-employee workflows, dependencies, install/enable/disable, and dependency protection.
- **Employee packages**: `opc-employee-package` v1 with checksum, dry-run, default-disabled install, rollback, and audit.
- **Finance/project depth**: CFO/accounting/tax/business-reporting scope for finance; full lifecycle, milestones, Gantt/baseline/critical path, EVM, and OKR linkage for project supervision.
- **Governance**: SRS/IRS/SDD/DBDD/STP/STD/STR, UML, process assets, and local `spec:check`/`docs:check` gates.

## Install / upgrade

```bash
npm ci
cp .env.example .env       # fill OPC_PG_DSN / OPC_TEST_DSN
npm run migrate            # business database
npm run migrate:test       # test database
npm run typecheck
npm run test:unit
npm run spec:check
npm run docs:check
```

DSH profile: use `cordis.patch.yml` and provide `OPC_PG_DSN`, `OPC_ARCHIVE_DIR`, and `OPC_TIMEZONE`.

## Known limitations

- Integration tests passed in CI (68/68). A local run still requires `OPC_TEST_DSN` and a reachable PostgreSQL 17 + pgvector test database.
- Real DSH Web host slot/session-event/memory-plugin contracts still need end-to-end verification.
- Domain implementations for most employee lines (tables/tools/workflows) are Phase 2; manifests and requirements are ready.
- Employee packages are manifest-only today; workflow/config file export and signature verification are planned.
- `spec:check`/`docs:check` are lightweight local gates; stricter external CD-PTC gates remain optional.
