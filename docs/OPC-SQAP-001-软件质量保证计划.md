# OPC-玄机 · 一人公司中枢 软件质量保证计划（OPC-SQAP-001）

本文解决“凭什么说这个软件是合格的、谁来保证、用什么证据保证”的问题。SRS 定义验收标准，STP/STD 定义怎么测，本文定义**质量目标、评审与审计、度量、不符合项处理**，确保“写的人、测的人、批的人”不混为一谈。使用者与时机：开发在提交前看第 4、5 章；测试在设计与执行时看第 3、4 章；评审在 G1–G4 与月度复盘时看第 6、7 章。本文的指标目标为**可配置默认值**；当前实测值来自 `docs/OPC-STR-001-测试报告.md` 与 CI run `42153267527`。

## 1. 目的与范围

### 1.1 目的

用**可复核的证据**回答四个问题：

1. 需求是否都被实现并验证？（追溯）
2. 实现是否越层、越权、越界？（评审）
3. 质量是否稳定，还是一次性通过？（度量）
4. 发现问题后是否真的修好，而不是绕过？（不符合项闭环）

### 1.2 范围

覆盖中枢平台、流程、调度、Web 表现层、员工 manifest/员工包、HTTP/工具契约、数据层与文档。不覆盖：老板业务数据的正确性、外部 DSH 宿主自身质量、第三方插件质量。

## 3. 组织与职责

### 3.1 质量职责分离

| 活动 | 执行 | 复核 | 批准 |
| :--- | :--- | :--- | :--- |
| 写代码 | 开发组 | 另一名开发/Agent | 项目集成者 |
| 写测试 | 开发组或独立测试 | 集成验证组 | 项目集成者 |
| 执行测试 | CI / 集成验证组 | 集成验证组 | — |
| 写文档 | 文档组/开发 | 集成验证组 | 项目集成者 |
| 门禁判定 | 集成验证组 | 项目集成者 | 老板（重大） |
| 流程产出评判 | 独立 Verifier | 集成验证组 | — |
| 发布 | 项目集成者 | 集成验证组 | 老板 |

**硬规则**：生成者不评判自己的产出；独立 Verifier 与 coding agent 不共用模型配置与上下文（产品设计 §8.6.9.2）。

### 3.2 质量责任矩阵

| 角色 | 对质量负责的事 | 不负责的事 |
| :--- | :--- | :--- |
| 开发组 | 代码正确、可读、可测、迁移可回滚 | 不自行降低验收标准 |
| 集成验证组 | 测试充分、证据可复现、门禁结论 | 不改实现迁就测试 |
| 文档组 | 文档与代码一致、编号与追溯 | 不写未实现能力 |
| 项目集成者 | 门禁、偏差、发布、过程资产 | 不替老板做业务取舍 |
| 老板 | 目标与优先级、重大风险接受 | 不审代码、不签技术细节 |

## 4. 评审与审计

### 4.1 评审类型

| 评审 | 时机 | 输入 | 输出 | 不通过后果 |
| :--- | :--- | :--- | :--- | :--- |
| 需求评审 | G1 | SRS/IRS/员工分册/spec | 评审记录、PA | 不进入设计 |
| 设计评审 | G2 | SDD/DBDD/主会话 Agent 设计 | 偏差登记、PA | 不进入编码 |
| 代码评审 | 每个 PR | diff、测试、迁移 | approve/comment | 不合并 |
| 测试评审 | G3/G4 | STP/STD/测试代码/STR | 覆盖结论、PA | 不发布 |
| 发布评审 | Release | 发布说明、CI、检查单 | 发布批准、tag | 不发布 |
| 月度复盘 | 每月 1 日 | 指标、事故、技术债 | 改进项、PA | 进入下月计划 |

### 4.2 代码评审检查单

- [ ] 是否越层：员工是否直连库、是否绕过中枢写审计、是否递归派工。
- [ ] 是否越权：视图是否返回敏感字段、令牌是否超范围/超时、审计是否可改。
- [ ] 是否幂等：写节点是否有 `instance_id + node_id` 幂等键。
- [ ] 是否可测：新增逻辑是否有单测/集成测试。
- [ ] 是否可回滚：迁移是否只追加、破坏性变更是否有备份与回滚说明。
- [ ] 是否同步文档：接口/表/命令变更是否更新 IRS/DBDD/README。
- [ ] 是否留痕：派工、裁决、导出、删除是否写审计。

### 4.3 质量审计

| 审计 | 频率 | 方法 |
| :--- | :--- | :--- |
| 门禁审计 | 每门禁 | 对照判据逐条核验，证据登记 PA |
| 配置审计 | 每次发布/每季度 | 见 `OPC-SCMP-001` 第 8 章 |
| 测试有效性审计 | 每季度 | 抽查测试是否真断言、是否只测 happy path |
| 文档一致性审计 | 每季度 | 文档声明 vs 代码事实，更新偏差登记 |
| 安全审计 | 每季度/发布前 | 密钥、权限、敏感字段、审计只追加 |

## 5. 验证与确认

### 5.1 验证（做得对不对）

| 层次 | 方法 | 命令/位置 | 通过标准 |
| :--- | :--- | :--- | :--- |
| 静态 | 类型检查 | `npm run typecheck` | 0 错误 |
| 规格 | 规格门禁 | `npm run spec:check` | PASS |
| 生成物 | spec 生成一致性 | `node scripts/gen-spec.mjs --check` | PASS |
| 文档 | 文档门禁 | `npm run docs:check` | PASS |
| 单元 | `node --test test/unit` | `npm run test:unit` | 100% |
| 集成 | `node --test test/integration` | `npm test`（需测试库） | 100% |
| 契约 | `spec.test.ts` | `npm test` | operation/路由/表全对账 |
| 安全 | 权限/密钥/敏感字段检查 | 人工 + 测试 | 无高危 |
| 性能 | 健康检查与关键查询 | 手工/基准 | 达标或标注 |

### 5.2 确认（做的是不是老板要的）

- 需求由老板/产品确认；验收场景必须能映射到老板能理解的结果。
- 主会话 Agent 的验收用 `OPC-SDD-002` 的 AC-AGT-01..10：老板 3 分钟内看懂、30 秒能选。
- 关键业务口径（税、补贴、合同风险）由老板或专业机构确认；软件只保证“按配置执行 + 标注来源”。

### 5.3 测试数据与生产隔离

- 集成测试只连 `OPC_TEST_DSN`；`NODE_ENV=test` 下与业务库相同会拒绝启动。
- 三关测试/回放/影子使用隔离测试空间，审计标 `test_mode=true`。
- 测试库串行执行（`--test-concurrency=1` + advisory lock），避免清库死锁。

## 6. 度量

### 6.1 过程度量

| 指标 | 口径 | 目标 | 数据源 |
| :--- | :--- | :--- | :--- |
| 门禁一次通过率 | 首次即通过的门禁 ÷ 总门禁 | ≥ 80% | PA 记录 |
| 测试通过率 | 通过用例 ÷ 执行用例 | 100% | 测试输出 |
| 缺陷逃逸率 | 发布后发现缺陷 ÷ 总缺陷 | ≤ 10% | 事故/issue |
| 回归失败率 | 回归失败次数 ÷ 回归次数 | ≤ 5% | CI |
| 文档门禁通过率 | PASS 次数 ÷ 执行次数 | 100% | CI |
| 偏差关闭率 | 已关闭偏差 ÷ 登记偏差 | ≥ 90% | SDD 10.2 |

### 6.2 产品质量度量

| 指标 | 口径 | 目标 |
| :--- | :--- | :--- |
| 需求覆盖率 | 有 AC/测试映射的需求 ÷ 总需求 | 100% |
| 契约一致率 | 对账一致的 operation/表 ÷ 总数 | 100% |
| 审计覆盖率 | 应记审计的动作 ÷ 实际记录 | 100% |
| 敏感字段暴露数 | 视图/日志/面板中出现原值 | 0 |
| 未确认不可逆动作数 | 未经确认即执行 | 0 |
| 降级正确率 | 降级路径符合设计的场景 ÷ 抽查场景 | 100% |

### 6.3 度量纪律

- 数字必须来自可复现命令或证据文件，不手工美化。
- 未覆盖项必须标注“未覆盖 + 归属阶段”，不得写成“通过”。
- 指标下降不隐藏；在周报/月报中说明原因与改进项。

## 7. 不符合项与纠偏

### 7.1 不符合项分级

| 级别 | 定义 | 例子 | 处理时限 |
| :--- | :--- | :--- | :--- |
| 严重 | 越权、审计可改、敏感数据泄露、不可逆动作未确认 | 员工直连客户敏感表 | 立即停止发布，24h 内修复 |
| 主要 | 需求未实现、契约不一致、测试失败 | 路由与 api.yaml 不符 | 本门禁内修复 |
| 次要 | 文档缺项、命名不一致、注释缺失 | 文档缺自检清单 | 下次提交前修复 |
| 观察 | 已知限制、Phase 2 占位 | 真实 Verifier 未接 | 登记 RMP/SDD 10.1 |

### 7.2 纠偏流程

```text
发现 → 记录（问题、证据、影响）→ 分级 → 定责/定期限 → 修复 → 复验 → 关闭
```

- 严重项必须写 PA 记录，并在发布说明“已知限制”中体现（若未修复不得发布）。
- 主要项在 G3/G4 门禁复验；未关闭不放行。
- 观察项进入 `OPC-RMP-001` 风险登记，季度复盘。
- 不允许“改测试迁就实现”或“删用例让门禁变绿”。

### 7.3 例外与豁免

- 例外必须书面记录：原因、影响、补偿措施、有效期、批准人。
- 安全、审计、不可逆动作三类**不允许豁免**。
- 豁免到期自动失效，需重新评估。
