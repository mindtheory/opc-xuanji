## 1. 目的与范围

### 1.1 目的

把“一人公司中枢”从产品设计推进到可运行、可审计、可交付的 DSH Bundle 插件，并在每个阶段留下可复核的证据。计划的对象是**软件交付过程**，不是老板的经营计划。

### 1.2 范围

| 在范围内 | 不在范围内 |
| :--- | :--- |
| 中枢平台：视图授权、令牌、冲突、审计、流程注册/评判/诊断 | 老板的经营目标、客户取舍、人员评价 |
| 11 条员工线的需求、manifest、可插拔与员工包 | 各员工线的完整业务实现（Phase 2 分线落地） |
| HTTP `/api/v1` 契约、31 个 `opc_*` 工具、15 个定时任务 | DSH 宿主本身的开发 |
| PostgreSQL 17 + pgvector 数据层与迁移链 | 生产环境网络、备份、等保测评 |
| 软件工程文档、测试、CI、发布与过程资产 | 市场推广、销售、客户成功运营 |

### 1.3 当前基线

- 版本：**v0.1.0**，发布日期 2026-11-06，Git tag `v0.1.0`。
- 交付快照：Git tag `v0.1.0`；分支 `main`。
- 质量证据：CI run `42153267527`；单元 25/25，集成 68/68，typecheck、gen-spec、spec、docs 门禁全绿。
- 规模：66 实体、6 条迁移、62 个 HTTP operation、31 个工具、10 个任务、19 个错误码、8 个视图。

## 2. 项目目标与成功标准

### 2.1 阶段目标

| 阶段 | 目标 | 完成判据 |
| :--- | :--- | :--- |
| P0 立项 | 范围、原则、非目标达成一致 | G0 通过，PA-OPC-001 登记 |
| P1 基线 | 中枢 + 财税/行政/客户 + Web v1 + 员工包 v1 可用 | v0.1.0 发布，CI 全绿 |
| P2 扩展 | 法务/项目/情报/货栈/车务 + 会话桥/记忆桥 + 雷达 | 各线需求与实现通过 G4 |
| P3 进化 | 技能→流程固化、分阶段回滚、驾驶舱增强、员工包签名 | G6 复盘通过 |

### 2.2 成功标准

1. **可运行**：`npm run serve` 能起服务，`/api/v1/health` 返回 PG 与 pgvector 正常。
2. **可验证**：单元、集成、契约、文档、规格五类门禁在 CI 全绿。
3. **可审计**：派工、写入、裁决、导出均有审计记录，哈希链可校验。
4. **可交接**：新接手者按 README 与 SDD 第 9 章能在 1 天内完成部署与排障。
5. **可演进**：Phase 2 能力在 SDD 10.1 有清单、有归属、不伪装成已实现。

## 3. 组织、角色与职责

一人公司项目不设庞大组织，但**职责必须分开**，避免“自己写、自己测、自己批”。

| 角色 | 承担者 | 职责 | 不做什么 |
| :--- | :--- | :--- | :--- |
| 老板 | 项目所有者 | 目标、优先级、预算、不可逆动作 | 不审代码、不操作流程 |
| 项目集成者 | 主会话 Agent / 指定负责人 | 计划、排期、门禁、发布、过程资产 | 不替老板做业务取舍 |
| 开发组 | 开发 Agent / 工程师 | 设计、编码、迁移、单测 | 不自行降低验收标准 |
| 集成验证组 | 测试 Agent / 工程师 | 集成测试、契约测试、回归、证据 | 不改实现来迁就测试 |
| 文档组 | 文档 Agent / 工程师 | SRS/IRS/SDD/DBDD/STP/STD/STR/管理文档 | 不写代码里没有的能力 |
| 独立 Verifier | 独立模型配置的 Agent | 流程产出评判、三关测试判定 | 不与执行 Agent 共用上下文 |

### 3.1 RACI（关键活动）

## 5. 生命周期与阶段门禁

```text
G0 立项 → G1 规格 → G2 契约 → G3 实现 → G4 验证 → G5 发布 → G6 复盘
```

| 门禁 | 判据 | 证据 | 不通过后果 |
| :--- | :--- | :--- | :--- |
| G0 立项 | 范围、原则、非目标、成功标准确认 | `docs/过程资产/G0/立项与范围.md` | 不进入需求 |
| G1 规格 | SRS/IRS 完整，`spec:check` 通过，需求可追溯 | `docs/过程资产/G1/规格门禁.md` | 不进入设计 |
| G2 契约 | spec ↔ DDL ↔ 路由一致，SDD/DBDD 评审通过 | `docs/过程资产/G2/契约门禁.md` | 不进入编码 |
| G3 实现 | `typecheck` + 单测通过，无越层依赖 | `docs/过程资产/G3/实现门禁.md` | 不进入集成 |
| G4 验证 | 集成/契约测试通过，STR 出结论 | `docs/过程资产/G4/验证门禁.md` | 不发布 |
| G5 发布 | 版本说明、CHANGELOG、tag、发布检查单 | `docs/releases/` | 不对外 |
| G6 复盘 | 目标达成、偏差登记、Phase 2 清单 | 复盘记录、PA 索引 | 不进入下一阶段 |

门禁规则：**证据必须能在 `pa-index.md` 找到；找不到即视为未通过。** 口头结论、聊天截图不作为门禁证据。

## 7. 开发流程与工程约定

### 7.1 顺序

`spec → docs → code → tests`

1. 需求变更先改 `spec/opc-xuanji/*.yaml`。
2. 同步修改 SRS/IRS/SDD/DBDD/STP/STD。
3. 再改代码与迁移。
4. 最后补测试与证据，跑门禁。

### 7.2 分支与提交

- `main` 受保护；功能/修复走短分支 + PR。
- PR 必须通过 CI（typecheck、单测、gen-spec、spec、docs）后才可合并。
- 迁移只追加，不改历史文件；文件命名 `NNNN_描述.sql`。
- 提交信息用 `[release]`、`docs:`、`chore(ci):`、`fix:` 等前缀，与现有历史一致。

### 7.3 本地门禁命令

```bash
npm ci
npm run typecheck
npm run test:unit
node scripts/gen-spec.mjs --check
npm run spec:check
npm run docs:check
npm test           # 需 OPC_TEST_DSN
```

### 7.4 文档约定

- 每份文档必须有 frontmatter、`自检清单`、`与其他文档的关系`。
- `doc_id` 唯一；`status` 走 `草稿 → 评审稿 → 已批准 → 基线 → 废弃`。
- 文档中的数字必须能回溯到设计、DDL、测试输出或发布证据。

## 8. 估算、资源与外部依赖

### 8.1 资源基线

| 资源 | 基线 | 说明 |
| :--- | :--- | :--- |
| 运行时 | Node ≥ 24.9 | 原生类型擦除直接跑 `.ts` |
| 数据库 | PostgreSQL 17 + pgvector 0.8.0 | 单机 4C/16G 起步 |
| 宿主 | DSH ≥ 0.2.1 | Bundle 插件装配 |
| CI | GitHub Actions | Node 24.9/24/26 矩阵 + PG17 service |
| 存储 | 本地磁盘 | 审计归档 `OPC_ARCHIVE_DIR` |
| 人员 | 老板 + AI Agent 组 | 不设全职团队 |

### 8.2 外部依赖与失效影响

| 依赖 | 失效影响 | 应对 |
| :--- | :--- | :--- |
| DSH 运行时契约 | 工具/路由/会话桥不可用 | 接口与实现分离；降级到独立服务；回写偏差 |
| PostgreSQL/pgvector | 全系统不可用 | 每日备份；RPO ≤ 24h、RTO ≤ 4h；健康检查 |
| GitHub Actions | 无法自动验证 | 本地门禁脚本可独立运行；证据手工归档 |
| 外部检索源（MCP/插件市场） | 雷达无结果 | 标注“本次未检索”，不生成推测 |
| 模型端点 | Verifier/对话不可用 | 本地模型优先；阻塞不降级为默认通过 |

### 8.3 估算口径

不按“人天”做虚假精确，按**可交付增量**估算：

- 小：单文件/单接口/单文档，1 次会话内完成。
- 中：跨 2–5 个模块或需迁移，1–3 次会话。
- 大：跨员工线/需外部契约核对，拆成中项后再排。

### 9.3 偏差处理

发现“文档说能做、代码没做”时：

1. 以代码事实为准，先在 SDD 10.2 偏差登记。
2. 判断是补代码还是改文档；涉及验收的必须老板知情。
3. 补测试或补证据，再更新文档状态。
4. 不把占位能力写成已实现。

## 10. 假设、约束与风险

### 10.1 假设

- 老板接受“先基线、后扩展”的节奏，不在 P1 追求 11 条员工线全量实现。
- DSH 运行时契约在 P2 前保持兼容；不兼容时有适配层。
- 测试库与业务库物理隔离；集成测试独占执行窗口。
- 老板愿意用 5 分钟完成公司档案 v1。

### 10.2 约束

- 单机部署，不引入 Redis/消息队列/ELK。
- 迁移只追加，不改历史。
- 审计只追加，应用账号最小权限。
- 不替老板做取舍；不可逆动作必须确认。

### 10.3 主要风险

见 [OPC-RMP-001 风险管理计划](OPC-RMP-001-风险管理计划.md)。本计划只列与进度直接相关的三条：

1. **DSH 契约漂移**导致 Web/工具返工 → 先做适配层与降级。
2. **员工线范围过大**导致 P2 延期 → 按“法务→项目→情报→货栈→车务”分批，每批独立验收。
3. **单点知识集中**在少数 Agent/人 → 文档、测试、PA 证据必须能让接手者复现。
